# CASMI26 V3: implemented research-to-inference pipeline

V3 adds fractional-mass features and complementary structure targets without
changing the original `predict.py`, old caches, or the best officially evaluated
model. It remains a **catalog retrieval model**, not a de novo decoder and not a
claim of score 1.0. The most recent verified public scores before V3 were 0.147
for baseline V1 and 0.112 for confidence V2. See the preflight evidence JSON.

## End-to-end run on ChemistryPC

From a current repository checkout:

```powershell
& 'C:\ProgramData\ChemistryRunner\envs\casmi26\python.exe' .\tasks\casmi_v3.py --stage all --epochs 10
```

The GitHub runner request uses the same script. Stages `prepare`, `fit`, `refit`,
`deliver`, and `tests` are separately available. The task runs the test suite
before any training. It does not call Kaggle or access provider credentials.
It reads the staged official corpus under the project's `data\external`, not
private files elsewhere in the user profile.

The new cache is `C:\ProgramData\ChemistryRunner\cache\casmi26\highres-v3`.
The original `official-v1` cache is read-only. Cache contents and the scientific
software contract are hashed. Finished stages can be reused only when their
identity matches; unknown unfinished output is not silently overwritten.
Failed temporary cache directories are retained for diagnosis.

## What is compared

The 8200-dimensional input preserves the original 4104 coordinates and adds
fractional-mass moments for fragment and neutral-loss bins. These moments still
compress the peak list. Structure targets are tautomer-normalized Morgan
radius 2 (2048 bits), Morgan radius 3 (4096 bits), and atom-pair (8192 bits).
Targets are generated from known training/candidate structures only.

Three models start from the same fixed molecule-held-out checkpoint: an
old-input/Morgan control, a high-resolution/Morgan model, and a high-resolution
three-target model. They receive the same ten extra epochs, seed, learning rate,
batch size, and hidden width. Fixed multihead weights and the no-change baseline
are compared on 800 unused calibration keys. The selected configuration is
written to disk before the 1600-key audit. All prior validation molecular keys
remain excluded from fitting, not just the selected evaluation subset.

The audit is inclusive-catalog and uses aggregated spectra. It is not a hidden
CASMI prediction, an external-catalog coverage estimate, or an independent
Bruker-only benchmark. Subgroup results are descriptive and cannot select a
new variant. A positive bootstrap lower bound versus the frozen baseline is
required before creating a full-data refit candidate.

## Output and inference

When the promotion criterion is met, the selected architecture is refitted on
all eligible training rows, starting from the previous all-data model. That
refit is never evaluated on the former held-out set. Its private train-only
bundle, executable notebook, and delivery ZIP are placed under:

```text
C:\ProgramData\ChemistryRunner\artifacts\casmi26\highres-v3\
    bundle\
    casmi26-v3.ipynb
    notebook-output\submission.csv
    notebook-output\submission.csv.report.json
    casmi-v3-delivery.zip
```

Inference uses the CURRENT query IDs and every valid spectrum in each group:

```powershell
python predict_v3.py --test data/test.parquet --train data/train.parquet --bundle C:/ProgramData/ChemistryRunner/artifacts/casmi26/highres-v3/bundle --output submission-v3.csv
```

`--routing neural`, `--routing confidence`, and `--routing legacy` provide
explicit comparisons. The confidence threshold/margin remains the frozen R03
0.95/0.05 rule; V3's neural audit does not establish that this router is optimal
on hidden data. None of these modes automatically replaces V1 as the official
champion. Mass-incompatible last-resort guesses are reported, never counted as
successful structural recovery.

The generated notebook embeds versioned project source and installs pinned
Linux dependencies offline. It discovers the current test mount rather than
hardcoding the 400 visible examples. Temporary source/dependencies are outside
the output directory. Model checkpoints contain numeric arrays, not executable
pickles. The bundle contains no test IDs, test predictions, or credentials.

## Evidence and submission control

Detailed protocol, training metadata, chosen weights, paired audit ranks and
validation results are stored in `artifacts\casmi26\research-v3`. The run report
and checksums record what actually completed; software tests alone do not prove
molecular accuracy. If the candidate fails the improvement criterion, no refit
is promoted and the original model is kept.

The V3 task makes **zero Kaggle uploads/submissions**. Two attempts were already
used within the agreed rolling 24-hour budget when this implementation started.
Future submissions must pass both the server-reported quota check and the
local journal/at-most-once safeguards. A new official score must come from the
server, not from validation or an oracle-descriptor audit.
